# Verification & Reference Integration Acceptance Matrix

This document provides the 4-tier verification matrix (`Unit`, `Integration`, `UI / DOM`, and `Security / Platform / Packaging`) and complete reference-to-production traceability across all eight reference repositories:

1. `openhands/OpenHands`
2. `milind-soni/OpenMausBot`
3. `deepseek-ai/deepseek-harness`
4. `Twigpine/openclaude`
5. `lidge-jun/opencodex`
6. `NousResearch/hermes-agent`
7. `anomalyco/opencode`
8. `google/elephant-goldfish-model`

Every feature is classified using one of five strict statuses:
- `verified` — Implemented, invoked by the production execution spine (`POST /api/chat/stream` -> `executeTaskDag()`), and proven by automated integration/E2E verification.
- `implemented and production-integrated` — Wired directly into the main request/desktop runtime and covered by automated verification.
- `implemented and unit-tested only` — Implemented in a production module and verified by direct unit/subsystem tests, invoked on-demand via API/tool rather than every chat turn.
- `partial` — Implemented with platform-conditional or optional external binary dependencies.
- `intentionally unsupported` — Upstream capability intentionally omitted for security or local-first architectural boundaries.
