## Strict Verification Classification Legend
To prevent conflating unit/fixture checks with live end-to-end execution, every capability below is classified using exact verification categories:
- **`VERIFIED (Live Inference Completed)`**: Executed end-to-end against a real live model endpoint or CLI binary and returned a completed model response.
- **`VERIFIED (Live Native Session Resume)`**: Executed multi-turn against a real CLI binary where Turn 2 resumed the native CLI session ID created in Turn 1 from the CLI's on-disk store.
- **`PARTIAL (Live Binary Init Only)`**: Executed the real installed CLI binary and verified initial JSONL handshake (`init` / `step_start`), but full model inference did not complete due to missing upstream cloud credentials.
- **`MOCK-VERIFIED (Protocol Fixture)`**: Verified against a local HTTP/child-process fixture reproducing the wire format (`SSE`, `JSONL`, tool calls, HTTP errors, timeouts).
- **`UNIT-VERIFIED (Arg / Schema / Policy Logic)`**: Verified deterministically at the function/class level (e.g., CLI spawn argument construction, JSON schema validation, secret scrubbing).
- **`NOT RUN`**: Not executed against a live upstream service or binary because credentials or binaries were unavailable on the machine.
- **`FAILED`**: Executed and failed.
